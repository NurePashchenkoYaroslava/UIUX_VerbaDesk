## Про проєкт
VerbaDesk — це внутрішня MVP вебсистема для невеликого бюро перекладів. Вона призначена для централізованої реєстрації, відстеження та координації виконання запитів на переклад від клієнтів. 
Цей репозиторій містить повний цикл проєктування UX/UI інтерфейсу: від аналізу вимог (Input Pack) до формування контрактів розробника (Screen Contracts) та фінальних макетів (Figma), виконаних згідно з методологією покрокового використання ШІ.

## Структура репозиторію

- Translation_Spec.docx — Адаптована вихідна специфікація вимог для бюро перекладів (єдине джерело істини).
- 01_Input_Pack_v0.1.md — Первинна вибірка UI/UX вимог (з виділеними питаннями Q-ID).
- Decision_Log.md — Журнал UX-рішень команди (D-01 до D-22), які закривають прогалини специфікації.
- Input_Pack_v1.0.md — Фінальний Input Pack із затвердженими рішеннями.
- 02_Screen_Map_v0.1.md — Карта екранів та матриця переходів між ними.
- 03_Screen_Contracts.md — Детальні контракти екранів, матриця прав, статусна модель та traceability.
- 04_Plan_Review.md - Звіт критичного аудиту контрактів (Крок G4) із зафіксованими та виправленими дефектами (DEF-01 - DEF-07).
- 05_Figma_Brief_v1.0.md — Технічне завдання (Brief) для генерації макетів у Figma Agent.
- ai-log.md — Журнал взаємодії з ШІ на всіх етапах (Кроки G1 - G6, F1, P1).
- 06_Review_Report.md — Фінальний незалежний аудит макетів (Review Report).
- BEFORE_REVIEW.fig - Сирий експорт макетів, згенерований Figma Agent до ручних втручань.
- AFTER_REVIEW.fig — Фінальні макети після ручного рев'ю, виправлення UI-дефектів та налаштування клікабельного прототипу.

## Архітектура системи (Screen Boundary)

Макет реалізує канонічний мінімум з 4 основних поверхонь без плодіння зайвих сторінок:
1. S-01 — Межа авторизації (Authentication boundary placeholder).
2. S-02 — Головний список заявок (стани: All, Important, Empty).
3. M-01 — Модальне вікно створення заявки (Create Issue).
4. S-03 — Деталі заявки (Issue Details). Всі елементи керування (Assignee, Priority, Status, Comments) знаходяться на цьому екрані.

## Ключові бізнес-правила (Matrix Highlights)
- Ролі: система є виключно внутрішньою. Користувачі — 2 Translator (Team Member) та 1 Manager (Team Lead).
- Важливі заявки (Important): формула Priority IN (High, Critical) AND Status != Closed. Заявки у статусі Resolved можуть бути важливими.
- Матриця прав:
  - Змінювати пріоритет та призначати перекладача може лише Manager.
  - Змінювати статус може лише Current Assignee (призначений на конкретну заявку виконавець). Роль Manager не дає автоматичного права змінювати статус.
- Візуалізація заборон: заборонені для конкретної ролі дії залишаються видимими, але стають неактивними (disabled). Вони не приховуються з інтерфейсу.
